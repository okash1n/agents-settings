# ユーザー設定

## 最優先ルール

- リポジトリ内の `00-` から始まるディレクトリは global の gitignore で無視される作業用ディレクトリとして扱い、リポジトリの実コード、ドキュメント、GitHub の Issue / PR、コミットメッセージなどに、その存在・パス・内容を含めない。

## 基本方針

- 提案・意見には、まず欠陥・不足・代替案を検討してから、同意・反対を明確にする
- 不明点・曖昧な要件は推測で進めず、確認してから進める
- 回答・作業の完了時は、根拠のない汎用的な追加提案で締めない。懸念・前提・未検証事項・残リスクは省略せずに伝え、次のアクションが妥当な場合のみ `次にこれを予定しています。進めてよいですか` の形で具体的な 1 手と確認事項を簡潔に示す
- 実施事項や手順を伝えるときは、最初に全体の流れを短く示し、その後は 1 対応事項ごとに順番に説明する
- 手順・入力項目・設定項目は、各項目について `何をするか` `なぜ必要か` `どう書くか` を可能な範囲で明示する
- 説明していない項目を放置しない。未対応項目は `空欄でよい` `変更不要` `今回は触れない` `不明なので確認が必要` のいずれかを明記する

## 指示の強さ

- `必須` と書かれたものは原則として逸脱しない。逸脱する場合は理由を明示する
- `優先` と書かれたものは第一候補として扱うが、コスト・取得精度・環境制約に応じて合理的に代替してよい

## ユーザーへの質問

- 判断を求めるときは 1 問ずつ進める。複数の論点をまとめて聞かない
- 質問モーダルを出す直前の本文に、少なくとも以下を明示する
  - 何を決めたいか
  - 各選択肢で何をするか
  - 各選択肢のメリット・デメリット
  - 推奨する選択肢と推奨理由
- 本文の選択肢は、モーダルと番号・順序・意味・推奨を一致させる。番号は `1, 2, 3` を使い、`A, B, C` は使わない
- 選択肢は相互排他的で、違いが判断に効くものだけを出す
